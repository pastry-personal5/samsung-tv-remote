# Version v2.0.0

Version v2.0.0 introduces a background Control API Server shared by the native
macOS interface and Claude Code through Streamable HTTP MCP. The server owns
TV connections, saved devices, pairing, remote commands and Wake on LAN.
Closing the GUI leaves the server available to other clients. An intentional
Stop persists until explicit Resume.

## Changes

- The GUI uses an authenticated local HTTP/SSE API for TV operations and state
  updates. Both clients share one selected TV, with guards that reject stale
  actions rather than sending them to a different target.
- Fifteen MCP tools expose TV setup and control through the same application
  policy. Settings → Servers provides Check, Connect, Verify, Disconnect and
  explicit repair for the Claude Code connection.
- Private operation lookup recovers retained results after a lost reply.
  Duplicate operation keys prevent repeated writes within the retention window;
  uncertain actions are never automatically replayed.
- macOS installation verifies the staged signature, settles the previous
  processes before replacement and retains the previous bundle for rollback.
  Publication locks protect cooperating app launches during replacement.
- Automated coverage includes combined GUI-client/MCP behavior, storage and
  process failures, installation rollback, removal/recovery, and synthetic
  TLS/WebSocket checks without a physical TV.

## Upgrade and recovery

The server uses a fresh profile separate from the legacy GUI profile. Legacy
TV records and pairing credentials are not imported; adding and pairing a TV
is an explicit setup step. Existing legacy data is retained.

Production bundles require an Apple Development or Developer ID signature.
Routine credential access is noninteractive; blocked access requires explicit
recovery. See the [installation and troubleshooting guide](../contribution-guide.md#install-and-update-the-macos-app)
for updates, retained-bundle rollback and removal/recovery.

## Acceptance status and limitations

Version v2.0.0 records the implemented server/client refactor; Phase 2 release
acceptance remains open. The full automated suite passed with four test
threads before the version bump. Default concurrency reproduced an existing
concurrent-helper timeout, which remains unresolved. Final signed lifecycle,
upgrade and credential
checks, actual Claude model-visible token/call measurements, keyboard and
VoiceOver review, physical-TV verification and hands-on removal/recovery are
still pending. See the [pending acceptance checklist](../phase-2/pending-acceptance.md)
and [Phase 2 acceptance review](../phase-2/milestone-11-review.md).

Sources, Apps and Text Input remain placeholders planned for Phase 3.
Command writes and Wake packets are reported separately from observed TV
responses; Play/Pause retains inferred command state rather than observed
playback state.
